# Desktop bridge (main edge) — 145-method RPC inventory

**Evidence:** shipped `dist/electron-preload/preload.cjs` + `dist/electron-main/main.cjs` (Grok Bot 0.24.0, SHA-256 verified).
**Confidence: A** for method names and arg styles (direct string evidence in shipped preload table);
**A-** for payload keys (destructured in main handlers); **B** for event-name completeness
(emit()-site scan; internal EventEmitter names filtered by a curated list).

## Wire protocol ("dune-rpc")

- Channels: `dune-rpc:<edge>:m:<method>` (invoke), `dune-rpc:<edge>:e:<event>` (broadcast),
  `dune-rpc:<edge>:probe` (method-existence probe used to distinguish handler-missing from transport failure).
- Single edge exposed to renderer: `"main"` with an events lane.
- Reply envelope: `{ ok: true, value } | { ok: false, failure: { code, detail } }`;
  error codes include `edge/unknown-method`, `edge/transport-failed`, `edge/handler-failed`.
- Preload exposes exactly two bindings: `desktop` (the method map) and `coordinatorPort`
  (a synchronous boot channel — see docs/subsystems/coordinator.md).
- Trust policy: each method carries a trust classification checked before dispatch
  (`EdgeTrustPolicyMissingError` when undeclared).
